## HIGH / HOLD: T70 silently misreads existing saves

`battle_root.gd` changed placement coordinates from the old TileMap world coordinates to canonical native flow coordinates, and changed `_rebuild_placement_from_sim` from `grid.world_to_cell` to `_sim_pos_to_cell`. The FlatBuffers snapshot version/load path did not change. Thus pre-T70 saves still return successful loads but restore incorrect presentation and occupancy.

Independently reproduced in `/tmp/pmf-t76-review`, with private `XDG_DATA_HOME=/tmp/pmf-xdg/chat-t76-legacy`:

1. Use `battle_root.gd` from `10889ac^` in the disposable game. Instantiate the modular battle, disable its process, call `debug_spawn_at_cell("spearman", 0, Vector2i(1,1))` and again at `(6,3)`, then `save_snapshot()`.
2. Saved defenders: IDs 10001/10002, positions **(364,296)** and **(556,520)**. Save succeeds.
3. Restore current T70 battle script and instantiate a fresh battle in the same private profile. `load_snapshot()` returns **true**, with both defenders still in native state.
4. Land occupants now contain only **`{(4,2):10001}`**. The first defender is mapped onto the outpost; the second maps outside the grid and disappears from occupancy. Native solids still represent original placement, so rendering, selection, placement locks and combat disagree.

Evidence: `/tmp/t76-legacy-save.log`, `/tmp/t76-legacy-load.log`; repro driver `/tmp/pmf-t76-review/game/tests/t76_snapshot_probe.gd`. New fresh-run coordinate round trips do not catch this compatibility failure.

**Required follow-up:** preserve the previous coordinate contract or implement explicit versioned compatibility for existing snapshots before accepting T70. Cover both fronts, placed/upgraded defenders, traveling heroes and mid-combat save state. Merely clamping cells or rejecting old saves loses player state. Positions alone are ambiguous between conventions; do not guess a version from one coordinate. Migration touches persistent simulation state and needs the native owner/lead, beyond a small reviewer fix. U4 and the index now explicitly record the hold.
